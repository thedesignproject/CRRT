# Complete resource-brief coverage

The user-provided `crrt-content.md` contains 120 content topics and 36 utility ideas. This expansion maps every item to a working public route: **120 guides + 36 tools/templates + 1 hub = 157 resource pages**. The full production build also retains the five existing non-resource public pages, for 162 HTML/Markdown pairs.

The initial PR covered 18 guides and three tools. This follow-up adds **102 guides and 33 utilities**, or **135 additional pages**. Existing URLs remain intact.

## Editorial approach

Each guide answers its numbered task with four practical steps, a specific fictional example, two questions, sources, and related reading. The pages are concise task guides; reading times reflect their actual length. No word count, keyword volume, traffic forecast, customer role, or business outcome is invented. Audience evidence remains the qualitative hypotheses in the brief.

Utility pages provide either a calculator/playground, local-image review surface, editable table, or structured document builder with copy/download. They use supplied inputs, preserve unknown data explicitly, and do not submit feedback or grant project access. The theme-review case is clearly fictional and is not presented as the resolution of issue 201.

The hub supports all 12 source categories plus track, resource-type, and text filters. Its featured tool section remains short; all resources remain present in public HTML.

## Quality gates

- Tests require every source topic ID (1–120) and utility ID (1–36) exactly once, unique document identities, existing links, and substantive public content.
- Calculator tests cover known fixtures, malformed input, chronological timestamps, missing phases, JSON limits, and export escaping. UI tests cover edits, review status, row operations, copy/download links, local file validation, and comparison controls.
- Catalogs and tool configurations hydrate from each document’s non-executable JSON. Articles receive only navigation and related-reading metadata; the hub receives the full browsing catalog. Extended tools load only on their own routes and hydrate their prerendered fields.
- Deployment routing splits known paths into bounded expressions so library growth does not produce one oversized regex.
- Hairline loads the three selected vanilla figures instead of its complete React registry. Fixed navigation uses canonical styles without downloading an unnecessary utility-class merge engine. Existing Google Analytics remains enabled.
- Lighthouse CI audits every resource three times per mobile/desktop profile across eight disjoint URL shards. No page is omitted; each job remains within its time limit.
- Local and CI reports are lab measurements. Index coverage, live crawler access, real-user metrics, and AI citations require separate production evidence.

See [quality commands](resources-quality.md) for reproduction and [the initial 22-page audit](resources-quality-audit.md) for the historical baseline. Current expansion measurements are recorded in `resources-full-quality.md`.
